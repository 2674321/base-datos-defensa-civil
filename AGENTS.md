## 3. Reglas técnicas obligatorias

- **El backend no depende de la edición manual de hojas:** `onEdit`/`onSelectionChange` son solo protección/normalización administrativa auxiliar. Toda la lógica principal se ejecuta mediante llamadas explícitas al backend (API JSON de §11) — el sistema debe funcionar completo desde la Web App aunque nadie toque las hojas.
- **Operaciones por lote, nunca celda a celda.** Usa `range.getValues()` / `range.setValues()` en vez de loops con `getRange(fila, col).getValue()`. Es la causa #1 de timeouts en scripts de Sheets.
- **Busca columnas por encabezado, no por letra/índice fijo.** Si alguien reordena columnas en la hoja, el código no debe romperse. Los mapas de columnas viven en `00_Constantes.js`.
- **Triggers simples (`onOpen`, `onEdit`) vs. instalables:** los simples no pueden usar `UrlFetchApp`, enviar correo en nombre del usuario, ni tocar servicios que requieren autorización. Para reaccionar a envíos de Form, usa un trigger **instalable** `onFormSubmit`.
- **Concurrencia:** si pueden llegar operaciones casi simultáneas y el script escribe en la hoja, envuelve la sección crítica con `LockService.getScriptLock()`.
- **Zona horaria:** usa `Session.getScriptTimeZone()` o la definida en `appsscript.json`; nunca asumas la zona horaria del servidor.
- **Secretos y configuración:** IDs de carpetas, direcciones de notificación, claves de API → `PropertiesService.getScriptProperties()`. Nunca hardcodeados en el código. Los parámetros de negocio (estados, categorías, vigencias) viven en la hoja `Config`, con sus valores por defecto en `00_Constantes.js`.
- **Manejo de errores:** todo trigger va envuelto en `try/catch`. En el `catch`, registra el error (ver logging) y, si el proceso es crítico, notifica al admin. Ningún trigger debe fallar en silencio.
- **Logging:** usa `console.log`/`console.error` (visibles en el panel de ejecuciones) y además escribe eventos clave en una pestaña `Log` de la hoja (timestamp, función, resultado) con `LockService` y autoacote de filas.
- **`appsscript.json`:** cualquier cambio que agregue un servicio avanzado (Sheets API, Drive API), un scope OAuth nuevo o un trigger debe reflejarse ahí también. Pide confirmación antes de ampliar `oauthScopes` — usa siempre el mínimo necesario.
- **Cuotas a tener presentes** (típicas para cuenta personal; en Workspace algunos límites son mayores — confirma en la página oficial de cuotas si te acercas a ellos):

| Recurso | Límite típico |

## 5. Flujo de trabajo con OpenCode

1. **Plan primero.** Para cualquier cambio que no sea trivial, usa el modo *Plan* de OpenCode: resume en 3–5 líneas qué vas a tocar y por qué, antes de escribir código.
2. **Cambios pequeños.** Una función o un trigger por iteración. No refactorices varios archivos a la vez "de paso".
3. **Verifica, no asumas que funcionó.** Apps Script no tiene tests automáticos triviales: después de cada cambio, indica los pasos manuales de verificación (qué función correr desde el editor, qué mirar en `Log`, qué probar).
4. **`clasp push` al terminar cada cambio** (ver §6 — el agente puede hacerlo solo), y revisa `clasp logs` si algo no cuadra.
5. Si una tarea requiere encadenar muchas llamadas a herramientas (leer 8+ archivos, refactor grande, arquitectura nueva), dilo explícitamente y sugiere partirla en sub-tareas: este modelo rinde mejor en tareas cortas y acotadas que en cadenas largas.

### 9.2 Datos e identificadores

- **ID único = N° correlativo en hoja** (patrón CESFAM: contador `maxId+1`). Sin `Utilities.getUuid()`. El N° es automático: `onEdit` revierte cualquier edición manual (04_Eventos.js).
- **IDs con prefijo** en Catálogo/Inventario/Entregas (`E-001`, `INV-001`, `ENT-001` — `_siguienteIdPrefijo`, 01_Utilidades.js).
- **Estados por entidad (no mezclar conceptos):** Inventario = `Disponible, Entregado, Dañado, Extraviado, Baja` ("Entregado" solo en unidades con N° Serie); Entrega = `Pendiente de devolución, Devuelto, Devuelto parcial, Dañado, Extraviado, Entregado` (final sin devolución requerida); Catálogo = Activo/Inactivo.
- **RUN = clave natural secundaria** (validación módulo 11), con normalización de sinónimos (con/sin guion, con/sin puntos, DV pegado o calculado). **RUN único**: el registro rechaza duplicados (muestra el N° y estado del existente).
- **Relaciones por ID, nunca por nombre** (ej. `Entregas.VoluntarioID` → `Voluntarios.ID`, `Entregas.InventarioID` → `Inventario.ID`); los nombres se guardan como snapshot histórico, no como FK.
- Transferencias batch con **índice en memoria** (mapa RUN→fila) y un solo `setValues`.

### 9.4 Patrones obligatorios (extraídos del análisis de referencia)

- Operaciones por bloques (`getValues`/`setValues`), nunca celda a celda.
- **Índices de columnas fijos pero centralizados** en `00_Constantes.js` (mapa `COL`), con la regla de que **las columnas nuevas se agregan siempre al final** (nunca en el medio, para no desplazar índices existentes). Se prefiere este mapa centralizado a la búsqueda por encabezado en runtime: más rápido, sin ambigüedad, y la estructura la controla el código (`crearEstructuraBase`).
- Índices en memoria (mapa RUN→fila) para transferencias batch.
- Caché doble (variable global + `CacheService`, TTL ~30 s) para parámetros de Config.
- Anti-eco en `onEdit` vía `CacheService` (guardar clave antes de `setValue`, descartar el eco).
- Menú a prueba de fallos: `onOpen` aislado en `try/catch` para que los comandos queden disponibles aunque algo pesado falle.
- Config en hoja (defaults en constantes); Script Properties solo para preferencias (backup, avisos).
- Log con `LockService` + autoacote de filas; nunca lanza.
- Validaciones en celda: `requireValueInList` (≤50 opciones) o `requireValueInRange` hacia `_Opciones`; `requireCheckbox`; `requireDate`; `setAllowInvalid(true)`.
- Hoja de sistema oculta `_Resalte` + `onSelectionChange` para resaltar la fila activa (fase posterior, solo si aporta).

## 11. Arquitectura: WEB APP (interfaz principal — implementada ago 2026)

**La Web App HTML es la INTERFAZ PRINCIPAL del sistema.** Google Sheets NO es la interfaz para los usuarios finales: existe solo como base de datos, persistencia, administración técnica, configuración, auditoría, respaldo y mantenimiento. Los menús de la hoja son wrappers administrativos de respaldo.

### Capas (separación estricta)

```
Web App (HTML/CSS/JS)  →  google.script.run  →  Backend Apps Script  →  Google Sheets
```

- **Frontend (`13_UI_*.html`):** no conoce nombres de hojas, posiciones de columnas, IDs internos ni reglas de validación. Solo solicita operaciones al backend vía `google.script.run` (wrapper `App.pedir` en `13_UI_App.html`).
- **Backend:** único acceso a Sheets + lógica de negocio + validaciones + IDs + auditoría + concurrencia. Es la **fuente de verdad**.
- **Data access:** lecturas/escrituras por bloques; nunca celda a celda.

- **ago 2026 — CAUSA RAÍZ DEL "HTML BÁSICO" ENCONTRADA Y CORREGIDA (cadena de servido, 3 errores):** (1) `doGet()` usaba `HtmlService.createHtmlOutputFromFile('13_UI_Index')`, que **NO evalúa scriptlets** (los sirve como texto literal) → todos los `<?!= include(...) ?>` llegaban al navegador como texto plano → ni el sistema de diseño ni el JS de las páginas se cargaron NUNCA en producción (el CSS crítico inline del Index sí funcionaba porque no pasa por include). El diagnóstico previo ("caché") fue incorrecto: mi test jsdom resuelve los includes manualmente y eso enmascaró los bugs. Se aislaron con el experimento del usuario: CSS inline de diagnóstico (azul/rojo) SÍ se veía; CSS por include NO; y al activar los scriptlets, Apps Script reportó el error exacto. Deployment @9 (misma URL). **Lección: cualquier verificación local debe replicar el servido real (template engine de Apps Script + validación HTML de HtmlOutput), y comprobar que el HTML servido no contiene `<?!=` sin resolver ni provoca "malformed HTML".**
